# 案例 4：民意与一线情况摸底

> 场景标签：舆情/民意 · 随机走访 · 信访调研
> 涉及章节：ch08（信访调研）、ch10（随机调研）

## 场景

你负责一个用户体量很大的产品/社区/区域业务，想知道"用户到底在怨什么、盼什么"。等工单汇总和季度 NPS 是被动的——本书第八讲、第十讲的思路是：民意是"送上门的调研"，随机走访是主动出击，两者一接一访组合使用。

## 你怎么说

> 用怎样调研的方法帮我设计一套"用户怨情与需求摸底"机制：把工单、社群吐槽、评论区当成信访调研的素材来源，再加上不打招呼的随机用户回访。给出素材分类方法和"个案→共性"的挖掘流程。

## AI 执行路径

1. 读 `chapters/ch08-petition-research.md`（信访调研 vs 信访处置、六多筛选、两层问题分类）
2. 读 `chapters/ch10-random-research.md`（四个基调、覆盖面、随机走访纪律）
3. 产出：素材源清单 + 六多筛选规则 + 问题两层分类法 + 随机回访机制设计

## 方法论如何落地

- **五渠道盘点**：工单系统（体制内）、社群与评论区（体制外）、客服统计（研究成果）、管理层访谈（自上而下）、用户主动投诉（自下而上——最底层最真实）
- **六多筛选**：多问、多听、多沟通、多观察、多学习、多思考——从大量吐槽中只筛与调研主题相关的线索，防分散精力
- **问题两层分类**：政策设计类（产品机制本身错了→从个案查沿革找共性诉求→落到机制建议）与执行类（某次服务翻车→个案解决+同类排查）
- **随机回访四个基调**：充分信任一线同事、只听真话、盯住问题、当场研判；纪律是硬约束——"老乡的一个核桃都不能拿"对应到商业场景即：不拿回访换利益承诺

## 关键输出片段（模拟）

```markdown
用户怨情摸底机制 v1：

素材源（每日自动汇集）：
- 客服工单（分类标签） / 应用商店评论（1-3 星） / 社群吐槽关键词
- 每周随机抽 5 个"最近流失"用户电话回访（不打招呼式轻联系）

六多规则：接手任何工单先多问一层"之前还遇到过什么"；
凡带情绪的留言，先复述确认再归类，防误读。

两层分类：
A 类·机制问题（例：注销入口深 → 全站普遍）
   → 个案解决 + 出机制建议卡（进产品 backlog）
B 类·执行问题（例：某客服答复错误 → 同类排查）
   → 当个案处理 + 周报统计频次

随机回访纪律：只听不改口、不承诺无法兑现的修复、
不当场否定一线同事的处理——信任是听到真话的门票。
```
